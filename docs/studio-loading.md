# Studio loading and reflection environment

The original cinematic scene, materials, lighting intensity, camera film and wildlife remain in place. Warmup mounts one resource-resolving stage at a time, prepares its shaders while hidden, then reveals and yields before mounting the next stage. Arrival begins only after the staff stage has completed.

Three 185's native `compileAsync` polling cannot be cancelled safely when a material is disposed. `shader-warmup.ts` instead uses `renderer.compile`, the exposed `renderer.info.programs` handles and nonblocking `KHR_parallel_shader_compile` completion queries in cancellable animation frames. Every handle is validated before use; context loss and unexpected disposal use the existing scene-failure path. Without the extension, the functional fallback yields before rendering, but cannot promise nonblocking driver compilation.

## Original environment, baked rather than replaced

`public/studio/room-environment.bin` contains the exact half-float HDR CubeUV pixels generated by the installed Three 185 `RoomEnvironment` and `PMREMGenerator.fromScene(room, .04, .1, 100, { size: 128 })`. Baking avoids synchronous PMREM shader compilation on each Studio entry. It is an original generated reflection resource, not external photography or a replacement environment.

- Dimensions: 384 × 512, RGBA half-float, linear sRGB, CubeUV reflection mapping.
- Filtering: linear min/mag; no generated mipmaps; no vertical flip.
- Runtime: 16-byte `ABENV001`/little-endian dimensions header followed by half-float pixels. Size/header validation rejects incompatible data through the scene error boundary.
- CPU file data is loader-cached; each scene owns and disposes its own GPU texture. Retry clears the file-loader entry.
- The existing versioned asset URL and immutable caching apply. If baked bytes change after publication, bump the Studio asset revision in both `studio-assets.ts` and `next.config.ts`.

Regenerate from the repository root with Node 22 and installed system Chrome:

```powershell
node scripts/bake-studio-environment.mjs
```

Set `CHROMIUM_PATH` for another Chrome installation. The script uses a loopback-only module server, renders the exact original environment, and compares original versus restored textures across brass spheres at three roughness levels. It refuses differences above one 8-bit channel step. The recorded run was pixel-identical across 49,152 channels. Provenance, generation settings and asset SHA-256 are in `docs/studio-environment.json`.

Run `npm run verify`, `npm run build`, and the complete Studio Playwright suite after regeneration. Review real GPU profiles and screenshots; a successful build alone does not establish performance or visual equivalence on every device.
